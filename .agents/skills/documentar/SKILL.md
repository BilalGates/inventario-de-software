# documentar

## Principios

- **Un plan que no refleja la realidad es peor que no tener plan.** Se actualiza en el mismo commit que cambia la realidad.
- Escribe para quien lo leerá, no para ti: qué necesita saber para actuar.
- Un tema, un documento canónico. Si hay dos, uno enlaza al otro y declara cuál manda.
- Lo medible se genera con un comando, no se copia a mano.

## Tipos

| Tipo | Contiene |
|---|---|
| Decisión | Contexto, opciones, elegida, por qué, consecuencias. Fecha absoluta. No se reescribe: se supera con otra. |
| Plan | Casillas con criterio de hecho; marcar `[x]` al cerrar, con fecha o commit. |
| Runbook | Pasos exactos copiables, comprobación tras cada paso, cómo revertir. |
| Referencia | Qué es, dónde vive, cómo se usa. Ejemplos mínimos. |

## Estilo

- Frases cortas, voz activa, términos del proyecto.
- Fechas absolutas (`2026-10-01`), nunca "ayer" o "la semana pasada".
- Enlaces relativos a ficheros del repo.
- Nada de relleno: si una sección no aporta, fuera.
